# GrowthLab：资深数据分析师 5 分钟审阅路线

这份指南不是技术说明书。它回答两个问题：

1. 资深数据分析师拿到项目链接后，怎样最快判断候选人的分析能力；
2. 候选人怎样用业务语言展示框架，而不是堆砌 SQL、Python、FastAPI 或 Streamlit。

> 一句话定位：GrowthLab 把“老带新获客”和“新用户留存”统一成一条质量校正增长链路，用指标合同定位问题、用实验验证机制、用增量经济性决定是否上线，并把结论沉淀为可监控、可回滚的决策卡。

## 0–30 秒：先看管理层答案

打开仓库首页的决策驾驶舱截图，先回答：

- 当前目标差距在哪里；
- 哪个环节是可控断点；
- 策略改变了什么机制；
- 增量用户是否有下游质量；
- 是否值得上线；
- 上线后监控什么、何时回滚。

不要先解释技术。资深分析师首先判断的是：候选人能不能把一个模糊增长目标变成清晰、可证伪、可决策的问题。

## 30–90 秒：解释指标体系为什么合理

指标不是平铺的 KPI 清单，而是五层决策结构：

| 层级 | 核心问题 | 代表指标 |
| --- | --- | --- |
| 业务结果 | 是否缩小增长差距？ | 标准化 DAU；增量高质量活跃用户 |
| 获客数量 | 合格流量在哪一步损失？ | 曝光 UV → 邀请点击 → 分享成功 → 获客 → 激活 |
| 用户质量 | 获客是否留下来？ | exact D1/D7/D30；成熟 D1–7 活跃；Cohort 质量 |
| 增量价值 | 新策略是否创造净增量？ | 每万分流增量 D7；Contribution30；增量成本效率 |
| 护栏与可信 | 结论能否用于上线？ | 平均 LTV/CAC；样本；成熟度；DQ；SRM；SMD；分层耐久性 |

重点说明三件事：

1. 点击率是实验的主指标，因为诊断证据定位到了邀请点击环节；它不是最终业务目标；
2. D7 和 Contribution30 把“拉来多少人”升级为“拉来多少有质量、算得过账的人”；
3. 每个指标都有资格条件、分母、观察窗口、成熟度和结论边界，避免口径漂移。

## 90–180 秒：展示如何定位，而不是如何找相关性

诊断遵循“总量 → 分层 → 路径 → 机制”的顺序：

1. 先确认整体变化和数据是否可信；
2. 用渠道、设备、地域、版本和 Cohort 判断变化来自人群结构还是组内表现；
3. 用 Mix-Shift 把总体留存变化分成结构效应、组内效应和交互效应；
4. 用漏斗与路径找产品断点；
5. 把“其他环节稳定”保留为负证据，避免为每个波动编故事；
6. 最后才提出产品机制假设。

对应到两个案例：

- 老带新项目的主要断点是邀请点击率，产品机制是假设新版页面信息层级和 CTA 位置影响发现成本；
- 留存项目中，设备结构变化解释部分整体下滑，而稳定的注册/首页/浏览路径用于排除“新用户普遍不会使用产品”的假设。

这一步展示的是业务理解：相同的总体指标变化，可能来自流量结构、产品路径、用户质量或数据口径，不能直接跳到策略建议。

## 180–240 秒：展示因果纪律

实验页面应按以下顺序讲，而不是从 p 值开始：

1. 目标策略和业务目的；
2. 主指标、最终业务指标、护栏和相关指标；
3. 基线、MDE、显著性水平、功效、样本量和整周周期；
4. 稳定 Hash 分流和 assignment/exposure 双日志；
5. A/A、SRM、实验前 SMD 与数据质量；
6. 固定周期 ITT 估计、置信区间、业务显著；
7. 预设分层、多重比较、新奇效应和网络干扰；
8. 下游留存、Contribution30 与最终决策门。

需要主动说清：

- ITT 保留全部合格分流用户，是默认上线口径；
- Triggered/exposed 结果只用于机制诊断，因为它包含处理后的选择；
- 监控护栏不等于中途偷看主指标并提前停止；
- p < 0.05 只是证据之一，不自动等于值得上线。

## 240–300 秒：展示价值判断和可复用沉淀

最后不要用“实验显著，所以建议上线”收尾。应该用决策卡回答：

- 增量 D7 用户是否为正；
- Contribution30 是否为正，区间有多宽；
- 平均 LTV/CAC 与增量经济性是否被正确区分；
- 哪些预注册门已经通过，哪些未知会阻断上线；
- 上线后由谁监控什么指标；
- 什么情况下回滚；
- 下一轮实验要消除什么不确定性。

GrowthLab 沉淀的不是一组图表，而是四个可复用工作件：

1. **指标合同**：定义资格、粒度、分子、分母、窗口、成熟度、负责人、血缘和结论边界；
2. **诊断备忘录**：事实 → 解释 → 假设 → 行动 → 局限；
3. **实验预注册与健康清单**：目标、指标、MDE、样本、周期、分流、AA、SRM、SMD、护栏和停止规则；
4. **决策卡**：证据等级、增量效果、经济性、风险、负责人、监控和回滚。

## GROWTH：一套可以迁移到其他业务的个人方法论

| 阶段 | 必答问题 | 产出物 |
| --- | --- | --- |
| G — Goal | 要改变什么业务结果，指标口径是什么？ | 指标树、Metric Contract |
| R — Reliability | 数据、埋点、分母和成熟度可信吗？ | DQ/AA/SRM/SMD 检查 |
| O — Opportunity | 问题发生在哪个环节、用户或结构？ | 漏斗、Cohort、Mix-Shift |
| W — Why | 什么机制能够同时解释正证据和负证据？ | 可证伪假设、诊断备忘录 |
| T — Test | 什么设计能识别策略的增量效果？ | 预注册实验、ITT、区间与护栏 |
| H — Harvest | 增量是否有质量、有价值、可治理？ | Contribution30、决策卡、监控与回滚 |

该框架可以迁移到内容推荐、会员转化、促销、流失预警、渠道投放和产品功能评估；具体指标会变化，但“口径—可信—定位—机制—因果—价值”的决策顺序不变。

## 面试展示时不要这样说

- “我用了很多技术，所以项目很复杂。”
- “实验组涨了 5.29 个百分点，所以策略成功。”
- “p 小于 0.05，所以应该上线。”
- “标杆用户更常使用某功能，所以这个功能提高留存。”
- “ROI 高，所以增量价值一定高。”

更好的表达是：

> 我先把增长目标拆成数量、质量、价值和护栏，确认数据可信后用分层、Mix-Shift 和路径证据定位机制，再用预注册的固定周期 ITT 实验评估增量效果；最终把留存质量、Contribution30、不确定性、监控和回滚一起放进决策门。技术只是保证这套口径能被复现和审计。
