# V2 产品方案与业务验收标准

## 产品名称

- 中文：用户增长全链路分析与实验决策平台
- 英文：Growth Analytics Decision Platform
- GitHub：`growth-analytics-decision-platform`

## 产品定位

一份面向数据分析岗位的业务作品集。它不以“用了多少技术”为卖点，而是把两段脱敏项目沉淀为可复用的增长决策框架：

```text
监测异常 → 定义指标 → 拆解定位 → 保留负证据
→ 提出机制 → 实验验证 → 价值决策 → 指标治理
```

## 页面结构

1. **业务总览**：两个业务问题、四个核心结果、共同分析闭环、3 分钟招聘官路线。
2. **老带新增长**：指标树、版本诊断、推荐漏斗、产品假设、页面实验、首月 LTV/CAC。
3. **新用户留存**：窗口留存、用户分层、设备 Mix Shift、路径负证据、标杆用户、关注引导实验。
4. **实验中心**：目标、主指标与护栏、样本与周期、Hash、A/A、SRM、均衡、固定周期与风险。
5. **价值与渠道**：首月价值口径、激励指数、外部投放基准、经济性决策与边界。
6. **指标治理**：分子分母、窗口粒度、证据等级、决策记录和公开数据边界。

## 两个案例的统一与分离

统一的是分析方法：指标—定位—假设—实验—决策。

不统一的是生产数据：两个案例不声称来自同一家公司、同一时期或同一套用户明细。公开平台用统一的确定性模拟层支撑可运行性，但所有模拟数据均有显式标签。

## 冻结口径

- 老带新的最终业务指标是拉新用户数；邀请点击率是页面实验主指标。
- 次 7 日内留存是在新增后的 Day 1—7 至少回访一次，不等于 exact D7。
- 标杆功能渗透差异属于相关性，随机实验才支持关注引导策略的因果结论。
- `LTV / acquisition cost` 命名为首月 LTV/CAC；净 ROI 需用 `(LTV-CAC)/CAC`。
- 投放结构建议短期未落地，不写成已产生收益。
- 留存实验只披露“显著提升、p<0.05”；没有稳定绝对提升不补造。
- 裂变率没有冻结唯一分母，必须在指标合同中显示“待确认”。
- 标杆时长存在 18/20 分钟口述差异，公开版不写死。

## 视觉标准

- 首屏先讲业务问题、结果和决策，不出现数据库与统计术语墙。
- 每个页面至少有两类有效图表，且图表回答具体业务问题。
- 使用深海军蓝、钴蓝、青绿、琥珀和珊瑚的统一配色。
- 桌面端适合面试屏幕共享，移动端导航与图表不横向溢出。
- 数据状态、证据等级和结论边界可见但不抢主叙事。
- 不把 `SMD`、`SRM`、`Contribution30` 等高级指标放在业务首页。

## 公开边界

- 不公开真实公司、业务线、DAU 绝对规模、真实激励金额、生产 SQL、用户信息或内部系统。
- DAU 使用标准化指数，激励使用指数，实验大样本使用脱敏汇总事实。
- 页面明确区分 `anonymized narrative` 与 `synthetic demonstration`。
- 外部公开方法只用于校验 SOP，不把他人案例数字写成个人项目成果。

## 完成标准

- 六页 React 看板可在 GitHub Pages 直接访问。
- FastAPI + DuckDB 本地全栈真实可运行。
- 静态 JSON 与 API 的核心事实一致。
- Python、API、数据质量、TypeScript、React 构建、Docker 与浏览器验收通过。
- GitHub 首页以业务结果为主，提供 3 分钟招聘官路线和中文小白教程。
- 独立 QA 对照用户原始内容、公开 SOP、隐私边界和视觉效果后给出结论。
