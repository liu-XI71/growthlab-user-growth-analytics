# 用户增长全链路分析与实验决策平台

> 英文名：**Growth Analytics Decision Platform**

这不是一个“堆技术”的练习项目，而是一份可以直接发给招聘官的数据分析作品集。它用两个经过脱敏的增长项目，完整展示我如何从看板异常出发，搭指标、找原因、排除错误方向、设计 A/B 实验，并用用户价值和成本做最终决策。

**在线直接看：** [打开六模块看板](https://liu-xi71.github.io/growth-analytics-decision-platform/)

## 一、招聘官怎么看：不需要安装，3 分钟就够

招聘官只需要点击上面的在线链接，不需要下载代码，也不需要会 GitHub。

建议按这个顺序看：

1. **业务总览（60 秒）**：先看两个业务问题、四个关键结论和我的分析闭环。
2. **老带新增长（60 秒）**：看我如何从裂变率上涨中继续发现邀请点击断点，用页面改版实验验证，再用首月 LTV/CAC 决定是否上线。
3. **新用户留存（60 秒）**：看我如何用设备分层解释 Mix Shift，用稳定的产品路径排除卡点，再从标杆用户相关性走到随机实验因果性。
4. 如果时间充足，再看 **实验中心、价值与渠道、指标治理**，了解实验可信度、经济判断与方法论沉淀。

招聘官不需要看代码。代码与测试的作用，是证明这套看板和指标口径可以真实运行、可以复核，而不是代替业务分析。

## 二、这套作品集展示了什么能力

### 1. 指标体系不是 KPI 清单

我会区分：

- **最终业务指标**：真正要推动的业务结果，例如老带新的拉新用户数。
- **实验主指标**：策略直接作用的关键动作，例如邀请点击率。
- **诊断指标**：帮助确定问题发生在哪里，例如分享成功率。
- **护栏指标**：效果提升时不能被伤害的价值或风险指标，例如新用户首月 LTV/CAC。
- **数据质量指标**：决定实验结果能不能被相信，例如 SRM、埋点完整性和观察窗成熟度。

### 2. 定位问题时保留“负证据”

我不会把每张图都讲成成果：

- 老带新项目中，约 95% 的分享成功率说明主要问题不在微信分享环节。
- 留存项目中，产品核心路径转化没有明显下降，说明现有证据不支持“新用户不会用”是主要原因。

排除低解释力方向，和找到正向原因一样重要。

### 3. 区分描述、相关和因果

- 设备占比变化与总体留存下降，是**描述性解释**。
- 标杆用户关注渗透率是非标杆的 2.5 倍，是**相关性证据**。
- 随机 A/B 实验验证关注引导策略提升留存，才是**因果性证据**。

### 4. 显著之后还要判断值不值得

`p < 0.05` 不能自动等于上线。老带新项目还要确认增加激励后，首月 LTV/CAC 是否仍高于外部投放基准。当前版本为 `2.18× > 1.90×`，因此才形成“上线并持续迭代”的完整决策。

## 三、两个项目的完整业务链路

### 项目一：老带新获客增长

```text
外部拉新供给下降，DAU存在目标差距
→ 搭建拉新指标树与活动漏斗
→ 裂变率 2.14% 提升到 2.9%，但仍有再投资空间
→ 激励和留存玩法升级
→ 邀请点击率从约21%下降到17%
→ 分享成功率仍约95%，定位断点在邀请前
→ 产品/用研反馈：页面复杂、内容不聚焦、CTA在第二页
→ 简化页面并把邀请按钮放回首屏
→ 两周、数百万级脱敏样本 A/B：17%提升到23.5%，p<0.05
→ 首月LTV/CAC 2.18，高于外部投放1.90
→ 上线并持续迭代
```

公开版把 DAU 绝对规模标准化为 `81.25 / 100`，把真实激励金额改成 `100 → 160` 指数，不披露真实公司和内部数据。

### 项目二：新用户留存提升

```text
看板发现次7日内留存从48%下降到41%
→ 按渠道、设备、品牌、系统、年龄、性别、地域、城市等级分层
→ 平板留存比手机低约10pp，同时平板新增占比上升
→ 判断设备Mix Shift解释总体下降的重要部分
→ 建议在经济性约束下提高手机投放占比，但短期未落地
→ 检查下载到关注的产品路径，各环节转化没有明显下降
→ 排除基础使用卡点是主要解释
→ 用首月活跃天数和日均时长识别高频高时标杆用户
→ 标杆用户主页浏览与关注渗透率约为非标杆的2.5倍
→ 只形成相关性假设，不直接声称因果
→ 退出页面增加主页浏览与关注引导
→ 两周、约30万样本 A/B：次7日内留存显著提升，p<0.05
→ 策略推广并持续优化
```

这里的“次 7 日内留存”是：新用户在新增后的第 1—7 天内至少回来一次。它不是“精确第 7 天留存”。用户没有稳定提供实验的绝对提升百分点，所以公开页只展示“显著提升，`p < 0.05`”，不补造数字。

### 方式 B：在 GitHub 上看代码和说明

1. 打开仓库主页。
2. 往下看当前这份中文说明。
3. 点击页面上方文件夹：
   - `web`：React 看板页面；
   - `backend`：FastAPI 接口；

   - `scripts`：确定性模拟数据生成；

### 方式 C：在自己的电脑运行完整前后端

只有你想演示本地版本时才需要这样做。

#### 第一步：安装 Docker Desktop

安装并打开 Docker Desktop，等待左下角显示引擎已运行。

#### 第二步：下载项目

在 GitHub 仓库点击绿色 **Code** 按钮，再点击 **Download ZIP**。解压后进入项目文件夹。

#### 第三步：打开 PowerShell

在项目文件夹空白处按住 `Shift` 并点击鼠标右键，选择“在此处打开 PowerShell”。输入：

```powershell
docker compose up --build
```

第一次会下载依赖并生成 10 万用户的确定性模拟数据，通常需要约 3—4 分钟。看到服务启动后，在浏览器打开：

```text
http://localhost:8501
```

如果只想快速体验 5000 用户版本：

```powershell
$env:GROWTHLAB_DEMO_USERS='5000'
docker compose up --build
```

小样本版本只用于快速看页面，某些实验决策可能因为样本量不足显示 `DO_NOT_SHIP`，这是正确的分析规则，不是程序错误。

#### 第四步：停止项目

回到 PowerShell，按 `Ctrl + C`，再输入：

```powershell
docker compose down
```

## 五、页面怎么讲，不要堆技术

### 业务总览

讲清楚两个问题：一个解决获客数量，一个解决新用户质量；共同方法是从看板异常走到可验证决策。

### 老带新增长

重点讲：

1. 为什么拉新用户数是最终指标，邀请点击率只是实验主指标；
2. 为什么裂变率上涨后仍继续分析；
3. 如何用分享成功率稳定这条负证据锁定邀请断点；
4. 为什么页面简化是可证伪假设；
5. 为什么显著提升后还要看首月 LTV/CAC。

### 新用户留存

重点讲：

1. 次 7 日内窗口留存的准确口径；
2. 设备占比变化如何拉低总体指标；
3. 产品路径稳定如何帮助排除错误方向；
4. 标杆分析为什么只能说明相关；
5. A/B 实验如何验证完整引导策略的因果效果。

### 实验中心

不要背统计名词。只需说明：先写目标和指标，预先计算样本与周期，保证分流可信，不中途看到显著就停止，最终同时看统计显著、业务显著和护栏。

### 价值与渠道

重点说明 `价值 ÷ 成本` 是 LTV/CAC，不是净 ROI；比较渠道必须使用相同时间窗口和价值口径。

### 指标治理

说明你的沉淀能力：每个指标都有分子、分母、窗口和边界；每个结论都能追溯到事实、解释、假设、动作、决策与限制。

## 六、数据和隐私说明

公开仓库严格区分三类内容：

- **脱敏项目事实**：来自两段项目讲解的指标趋势、实验设计和结论。
- **标准化表达**：DAU 绝对规模改为指数，激励金额改为指数，移除真实公司与内部字段。
- **确定性模拟数据**：为漏斗、趋势和前后端运行生成的明细；它们只用于复现分析方法，不代表生产数据。

不会补造的内容包括：留存实验绝对提升、未提供的护栏、口述冲突的标杆阈值、裂变率未确认的唯一分母。
